## Intent Analysis

### 目標與使用者

公司同事、家人與朋友可在 LINE 私訊主動傳送一個搜尋點，得到附近三家可比較的餐廳，少花時間自行找午餐。位置可為任意選定地點，不代表本人當下所在，更不是持續定位。[intent][scope]

可選的一年精確位置／查詢歷史只供本人回顧；不同意保存仍能取得當次推薦。歷史管理與隱私保護是完整版本的必要成果，不是推薦完成後有空才補的項目。[scope SCP-04–SCP-09]

### 完成與價值判準

- 功能完成須涵蓋所有 SCP-01–SCP-09 及本文件相應驗收條件，並有可重現自動化與授權下真實整合證據；文件、原型、只有推薦或只有模擬成功均不能宣稱完整交付。[scope][practices]
- 產品價值沿用同事／親友使用幾次後的定性回饋：「是否幫助決定午餐」；不捏造滿意度百分比、採用率、實際試用名額或商業成效。[intent]
- 本輪只交付可測試版本，不正式上線；Q7 的人數／延遲是測試目標，不是外部服務保證或真人試用授權。[scope OUT-05][Q7]

### 用語與驗收約定

| 用語 | 定義 |
| --- | --- |
| 原始事件時間 | 通過來源及時效驗證的 LINE 事件時間；作查詢時間及一年期限起點，不以重送時間替換 |
| 接收時間 | 本服務收到事件的時間；用於事件時效與處理延遲量測，須能在測試中控制 |
| 本人 | 經已驗證 LINE 事件來源可靠辨識的私訊使用者；不信任輸入自行指定的他人身分 |
| 不可見 | 生效後所有本人查閱、分頁及其他服務讀取均不能再取得該歷史內容，不只是隱藏畫面 |
| 實體清除完成 | 本專案主要儲存、快取及可控副本中的位置／查詢內容均已清除；不把不可見當成完成 |
| 刪除全部的範圍 | 確認畫面清楚顯示的本人歷史範圍及截止時間；包含該範圍內尚在途的舊查詢，不包含畫面後的新查詢 |
| 驗收狀態 | 以下 Given／When／Then 是必須滿足的條件，尚未執行應用測試；每條全部成立才通過 |

## Functional Requirements

### FR1 — 私訊入口與位置輸入

限 LINE 一對一對話的主動位置搜尋及本人歷史操作；完整通過 FR1.1–FR1.3 才符合本項。[scope SCP-01、SCP-08]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR1.1 | Given 已驗證的本人私訊及有效 LINE 位置，When 告知／選擇已完成，Then 以傳送點查詢；Given 群組／多人對話，Then 不執行推薦或歷史查閱／刪除、不新增位置歷史，也不公開私人資料 | scope SCP-01；Q1 |
| FR1.2 | Given 文字地址、網址或其他不支援的搜尋輸入，When 接收，Then 引導傳送 LINE 位置，不自動解析成位置；Given 非有限數字、經緯度超出合法範圍或必填欄位缺漏，Then 拒絕搜尋／建歷史，不將預設值當作有效位置 | scope SCP-01；practices Code Style |
| FR1.3 | Given 來源驗證失敗或事件不符合 NFR2 時效，When 接收，Then 不呼叫餐廳來源、不建立歷史、不執行歷史權利操作；合法事件去重依 NFR2，不以接收成功宣稱推薦已送達 | scope SCP-08；constraints C-09；Q8 |

### FR2 — 告知、選擇與同意管理

預設不保存，分開說明當次位置處理、餐廳服務第三方傳輸及可選一年歷史；完整通過 FR2.1–FR2.3。[scope SCP-04][Q1]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR2.1 | Given 首次使用尚未完成告知／選擇，When 傳位置，Then 不呼叫餐廳服務，不保存或暫存位置等同意；顯示實際用途及所選第三方的告知、提供不保存／保存一年選擇，請本人選好後重傳。未選定第三方時只能使用受控模擬，不能拿空泛告知開放真人傳輸 | scope SCP-04、SCP-09；Q1；constraints C-06–C-08 |
| FR2.2 | Given 已選不保存，When 新傳有效位置，Then 可推薦但不新增位置／查詢歷史；Given 選保存一年，Then 只有選擇後的新有效查詢可保存，不回填選擇前資料。兩種選擇皆可用，不以同意保存換取基本推薦 | scope SCP-04–SCP-05；Q1 |
| FR2.3 | Given 選擇已完成，When 後續查詢，Then 沿用選擇且可在私訊隨時變更，不每次強制重問；Given 目的或保存條件變更，Then 變更用途生效前重新告知／確認，不默認沿用舊同意。撤回行為依 FR8，同意狀態資料依 NFR4 | scope SCP-04；Q1、Q8 |

### FR3 — 候選資格、距離與排序

以合法來源與可用資料決定三家餐廳，不加入個人化或隨機重抽；完整通過 FR3.1–FR3.3。[scope SCP-02–SCP-03][Q6]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR3.1 | Given 候選，When 篩選，Then 必須被來源分類為餐廳、有可回覆的名稱／座標／地圖資訊、未明確休息或停業，且未四捨五入的直線距離不大於 1,000 公尺；邊界 1,000 納入、大於 1,000 排除，不能改用步行距離或擴圈 | scope SCP-02–SCP-03；Q6 |
| FR3.2 | Given 合格候選，When 排序，Then 已知營業中先於未知，未知清楚標示，各組由近到遠；同距離用穩定店家識別排序。同一店家不因來源重複列項佔多個名額；同一受控候選集合的輸出順序可重現 | scope SCP-02–SCP-03、SCP-08；Q6 |
| FR3.3 | Given 至少三家不同合格店家，When 回覆，Then 只取排序後前三家，各含名稱、有來源依據的簡短理由與對應店家的地圖連結；理由可用距離／營業狀態，不捏造評價、保證好吃、即時營業或有座位；遵守所選來源必要標示及顯示權利 | scope SCP-02–SCP-03、SCP-08；Q6；constraints C-07 |

### FR4 — 推薦例外與部分成功

零結果不是外部故障，推薦成功不是保存成功；完整通過 FR4.1–FR4.3。[scope SCP-03][Q2、Q7]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR4.1 | Given 來源成功且只有一／兩家合格候選，Then 只回實際數量並說明不足；Given 零家，Then 明說範圍內無符合候選；皆不得複製、虛構或擴圈湊三家 | scope SCP-03；Q6 |
| FR4.2 | Given 來源故障、逾時或回應格式無法作可靠判讀，When 無法完成查詢，Then 明確回覆查詢失敗，而非查無餐廳或成功。有效回應內個別候選欄位不足可排除，但不能把整份無法判讀的回應當空清單；回覆期限及 LINE 不可用情境依 NFR1、NFR2 | scope SCP-03；practices Code Style；Q7 |
| FR4.3 | Given 推薦成功但歷史保存失敗，Then 保留推薦並明說未保存；Given 歷史查閱失敗，Then 不假稱沒有歷史；Given 刪除未受理或實體清除未完成，Then 不假稱已刪除。任何操作不能用部分成功代表全成功 | scope SCP-03、SCP-05–SCP-07；practices Code Style；Q7 |

### FR5 — 可選的一年查詢歷史

只保存本人同意的主動查詢供其回顧，完整通過 FR5.1–FR5.3。[scope SCP-05][Q2、Q3]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR5.1 | Given 有效新查詢、當時已同意保存且寫入時仍獲允許，When 餐廳查詢找到結果、零結果或外部失敗，Then 保存一筆對應本人歷史與真實結果狀態；未授權、無效、重複或被撤回／刪除界線擋住的事件不新增。保存服務失敗依 FR4.3，不假造寫入完成 | scope SCP-04–SCP-05、SCP-08；Q2、Q5、Q8 |
| FR5.2 | 歷史內容白名單為本人關聯、紀錄識別碼、查詢時間、精確經緯度、到期時間及簡短結果狀態。Given 資料與失敗路徑檢查，Then 不含完整訊息、自由文字位置名稱、餐廳清單或供應方原始回應；必要技術資料須依 NFR4 分類、用途及期限隔離，不能成為替代歷史 | scope SCP-05、SCP-08；constraints C-07；Q2、Q8 |
| FR5.3 | Given 原始事件時間，When 計算期限，Then 按 UTC 加一個曆年；UTC 2 月 29 日對應次年 2 月 28 日同一時刻。重送、重試、延遲寫入與後續新查詢皆不延長該筆期限；測試含一般年度、閏年及臺北日期與 UTC 日期不同的邊界 | scope SCP-07；Q3 |

### FR6 — 本人歷史查閱

Given 本人私訊輸入「歷史」，When 查詢成功，Then 按新到舊每頁最多五筆，可查看下一頁，每筆至少有臺北時間、搜尋點地圖連結及真實結果狀態，並有單筆／全部刪除入口。只回本人未刪且未到期資料；翻頁期間發生撤回、刪除或到期仍須套用當下存取與可見性規則。空歷史與查閱故障分開回覆，另一使用者不能藉改紀錄／分頁識別取得資料。這些條件及 NFR7 全部成立才通過。[scope SCP-05–SCP-08][Q2、Q3、Q5]

### FR7 — 本人確認後刪除

刪除單筆或全部均須明確範圍與本人確認；完整通過 FR7.1–FR7.3。[scope SCP-06–SCP-08][Q4、Q5]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR7.1 | Given 本人要求刪除，When 顯示確認，Then 綁定本人與單筆識別，或全部範圍及截止時間；五分鐘內可確認，達五分鐘即過期。取消／過期／他人操作不刪除，重複確認不造成新刪除；測試確認前、有效期邊界及之後 | scope SCP-06、SCP-08；Q5 |
| FR7.2 | Given 刪除確認有效且受理成功，Then 範圍內歷史立即不可見；全部刪除不涵蓋確認畫面後的新查詢，也不讓截止以前在途／延遲事件稍後寫回。單筆刪除只阻止該筆重建，不刪其他筆；受理失敗須明說未完成並保留安全重試方式 | scope SCP-06–SCP-08；Q4、Q5、Q8 |
| FR7.3 | Given 刪除已受理但尚有可控副本，Then 只能回「已受理，清除中」等真實狀態；只有全部應清內容完成清除後才能顯示已刪除。失敗安全重試及不含位置的告警，不用推播通知；完成時限依 FR9，不以長期保留技術代碼代替刪除內容 | scope SCP-06–SCP-08；Q4、Q8 |

### FR8 — 撤回及重新同意

Given 本人撤回保存且變更成功生效，When 有新查詢、尚未寫入的在途查詢或延遲舊事件，Then 不再新增歷史，但當次推薦可用；既有歷史仍按原期限可供本人查閱，提供另外確認後全部刪除，不把撤回當作刪除完成。Given 本人稍後重新同意，Then 只保存重新同意後的新查詢，舊事件或撤回期間查詢不得補存。若選擇更新無法完成，明說失敗，不假稱撤回／同意已生效。以撤回、寫入、重送及重新同意交錯測試全部成立才通過。[scope SCP-04、SCP-06、SCP-08][Q1、Q5][practices Code Style]

### FR9 — 到期、清除與復原

完整通過 FR9.1–FR9.3，不把一年期限、自動清除與本人提前刪除分割成可選交付。[scope SCP-07][Q3–Q5]

| ID | 需求與可觀察驗收條件 | 來源 |
| --- | --- | --- |
| FR9.1 | Given 現在時間達到某筆到期時間，Then 立即不可見／不可重新寫回；Given 到期前仍有效且未刪，Then 本人可讀。讀取保護不能等待排程刪除任務才生效，後續查詢不改舊期限 | scope SCP-07；Q3 |
| FR9.2 | Given 到期或成功受理刪除的生效時刻，Then 24 小時內清除主要儲存、快取及可控副本的位置／查詢內容。此期間只允許不可讀殘留供清除，不准繼續查閱／推薦使用；清除失敗、重試與超過期限須可被不含位置的紀錄辨識，超時即驗收失敗而非默認例外 | scope SCP-07–SCP-08；Q4 |
| FR9.3 | 第一版不得建立含位置歷史的持久備份／匯出；選定服務的複本及自動備份亦須符合不可見與清除上限，無法符合須回報阻擋真人保存。Given 復原或災損演練，Then 已刪／到期內容不再可見；接受因無歷史備份而無法救回資料的取捨，不宣稱有歷史復原保證 | scope SCP-07；constraints C-05；Q4 |

## Non-Functional Requirements

### NFR1 — 小規模負載與回覆時間

- 來源：[scope SCP-09][constraints C-13][Q7]。最多 20 個測試身分；用合成身分先做每秒一筆有效查詢持續五分鐘（300 筆）的持續負載，另測同時五筆；不是實際招募名額或固定帳號上限。
- 接收回應 p95 ≤ 一秒；從有效事件到達服務至 LINE 接受結果回覆的 p95 ≤ 五秒，涵蓋正常及可回覆的受控故障。處理期限十秒；期限內預留失敗回覆處理，逾時結果不能冒稱成功，不改推播。LINE 接受回覆不等於使用者裝置已看到。
- 測試需記錄環境、時鐘、樣本數、持續／併發場景、供應方及 LINE 延遲設定、錯誤與未回覆數。p95 用排序後第 `ceil(0.95 × 樣本數)` 筆，不只挑成功餐廳結果；測試中可回覆但未回覆的樣本不能刪除以美化成績。
- 驗收：上述場景逐項符合時間及誠實回覆要求；模擬餐廳故障但 LINE 可用時應有失敗訊息。LINE／網路不可用另作故障案例，不虛構接受回覆時間或送達；如實記錄失敗、不得宣稱該案例達成回覆目標。真實整合另留授權下量測，受控結果不能代替真實證據。

### NFR2 — 來源、時效、去重與安全重試

- 來源：[scope SCP-08][constraints C-09][practices Code Style][Q5、Q8]。
- 通過來源驗證後，僅接受原始事件時間位於接收時間前 24 小時至後五分鐘的事件（含邊界）。超出時效不查餐廳、不建歷史或執行權利操作；測試前後邊界，不能只靠短期去重表攔舊事件。
- 相同事件串行／併發／重送最多一筆歷史；回覆狀態不明不盲目重送、不推播補發，遵守 LINE 回覆憑證有效性；來源接收成功不代表處理及送達成功。
- 只重試能安全重放的操作，仍受處理期限、保存選擇、刪除界線及一年期限限制。驗收須包含重複事件、在途保存與撤回／刪除交錯、重新同意、技術代碼到期後舊事件再到達；不得建立重複或重生內容。

### NFR3 — 本人授權與資料隔離

- 來源：[scope SCP-05–SCP-08][constraints C-06][practices Testing Posture、Code Style]。
- 來源驗證與本人授權分開驗證；每次查閱、分頁、單筆／全部刪除、確認及保存設定都核對本人，不能只相信請求自行宣稱的 ID。管理存取不能成為公開查別人歷史的介面。
- 驗收用至少兩個合成使用者互換紀錄、分頁與確認識別；他人讀取／刪除／設定變更均拒絕且不洩漏內容，原擁有者資料不受影響。合法本人仍能完成流程，群組始終不能取得本人歷史。
- 必要傳輸／儲存存取保護、憑證管理及最小授權的具體機制由設計定義並提供正反例證據；未完成檢查不開放真人保存，不以測試覆蓋率替代安全結果。

### NFR4 — 資料最小化與分類期限

來源：[scope SCP-04–SCP-08][constraints C-05–C-07][Q1–Q5、Q8]。下表每列均為強制驗收條件，機制由設計選定，不能默認所有資料都保存一年。

| 資料類型 | 允許內容／用途 | 上限及驗收 |
| --- | --- | --- |
| 未完成告知／選擇的位置 | 不保留等待選擇，不作餐廳傳輸 | 選擇後必須重傳；檢查無待同意位置暫存或歷史 |
| 已選不保存的當次位置 | 僅當次必要記憶體處理 | 處理完成或十秒期限到達即釋放，不寫磁碟／持久佇列；檢查成功、逾時、故障及取消路徑 |
| 同意保存的查詢歷史 | FR5.2 白名單，限本人回顧 | 每筆 UTC 一個曆年，到期不可見，最遲 24 小時清除可控殘留；提前刪除同 FR9 |
| 去重、防重建、刪除作業資料 | 必要事件／紀錄代碼，不含位置或完整訊息 | 最多七天；到期清除後仍拒絕超過事件時效的重送，不重建已刪歷史 |
| 一般診斷與安全檢查證據 | 時間、隨機關聯代碼、狀態／錯誤類別及必要量測 | 最多 30 天；不含精確位置、完整訊息、原始使用者 ID 或秘密；僅授權開發／維護人員可讀 |
| 同意狀態 | 本人關聯、目前選擇、版本、變更時間，不含位置 | 保留目前有效選擇，撤回不抹掉拒絕狀態；服務終止後 30 天內清除，不另建無期限的同意歷史 |
| 餐廳供應方內容 | 僅授權允許的當次查詢／顯示及標示 | 不進一年歷史；快取或任何其他保留須先核對來源條款，沒有許可就不據此新增持久保存 |

使用受控時間驗證各類期限前、當下與之後，檢查應用、錯誤／追蹤紀錄及可控基礎設施存放處。平台若無法符合處理、日誌、複本或清除限制，必須回報，不能把位置轉存到另一套記錄繞過不保存選擇。

### NFR5 — 可觀察且不洩漏資料的失敗處理

- 來源：[scope SCP-03、SCP-07–SCP-09][practices Code Style、Testing Posture][Q4、Q7、Q8]。
- 必須能辨識接收拒絕、查詢成功／不足／零結果、來源故障、歷史保存／讀取失敗、刪除受理／清除中／完成／失敗及時間量測；只用 NFR4 允許的診斷內容，不另存位置或訊息。
- 驗收注入各種失敗：使用者文案與內部狀態一致，清除失敗產生可被授權維護人員看到的告警；不能因告警失敗而把未清資料說成已刪，不能把沒有紀錄當成操作成功。具體告警通道及狀態查閱互動留待設計，不新增對使用者主動推播。

### NFR6 — 資料權利與真人試用前提

- 來源：[scope SCP-08–SCP-09][constraints C-06–C-12][practices Deployment]。
- 真實整合前須驗證 LINE、餐廳資料及測試環境合法可用性；涉及費用先由提出者核准。位置與查詢的一年需求不能授權餐廳供應方內容的一年封存。
- 真人保存前須具備告知／同意、本人隔離、查閱、單筆／全部刪除、到期清除、存取安全、實際服務的日誌／複本設定及適用政策查核證據。尚未確認使用地區、公司政策及資料所在地時不得宣稱合規。
- 驗收為逐項前提與證據可追溯且無未處理衝突；任一缺項只能標記未就緒，不能用模擬成功或文檔核准開放真人保存。費用／授權衝突交由提出者決策，不自行縮短一年、刪減保護或啟用付費。

### NFR7 — 可理解的私訊互動

- 來源：[scope SCP-01、SCP-03–SCP-06][Q1、Q2、Q4、Q5]。
- 使用繁體中文，時間顯示 Asia/Taipei；營業未知、結果不足、故障、未保存、清除中與完成均有文字區別，不只依賴顏色或圖示。
- 驗收逐一檢查首次引導、位置輸入提示、推薦例外、歷史分頁、刪除範圍／有效期／取消及撤回流程；不須跳到新網站才能管理本人歷史。地圖連結可外開，但須指向當筆搜尋點或該餐廳，兩者不能混淆。

### NFR8 — 測試方法、覆蓋率與必要情境

- 來源：[scope SCP-09][practices Testing Posture]。Methodology 為 `test-after`：每個可測層實作後立即測試，邊界可連接即做整合測試，再擴充，最後驗證完整流程。
- 至少 80% 應用可測原始碼行覆蓋率；分母含未被測試載入的應用碼。依賴、產生碼、AI-DLC 框架與測試本身可排除，但清單須可審查，不能為過關縮小分母或降低門檻。
- 驗收須覆蓋下方 Acceptance Coverage 全部情境，包括隱私、生命週期、失敗、重送與併發；測試數量及整體百分比不替代關鍵案例。時間測試使用可控制時鐘，不等一年或真實期限才測。
- 平時使用合成位置／身分及受控供應方；授權後另驗證真實 LINE → 資料來源 → 回覆及完整本人歷史流程，兩種證據分列，沒有真實證據不標記全版本完成。

### NFR9 — 可重現建置、CI 與安全檢查

- 來源：[scope SCP-09][practices Way of Working、Testing Posture、Code Style、Deployment]。
- 本機及 CI 使用一致版本與命令，提供執行／測試說明；依選定語言設定格式、lint、建置、單元／關鍵整合測試及覆蓋率。必要檢查失敗、未執行或未達門檻一律不當通過，合併前均須滿足。
- 納入秘密、依賴及適用 SAST；已確認有效外洩憑證或 Critical／High 風險在處置前阻擋合併。誤報及限期例外由提出者檢視，不能取消隱私保護；工具、判讀及例外規則設計後驗證，不能以掃描為零當通過。
- 驗收須有上述命令與結果、排除清單和安全判讀證據，敏感內容依 NFR4 處理。DAST 只限獲授權受控目標，不自行掃描 LINE／供應方或上傳程式／資料到新服務。現在未授權建立分支、提交、合併、部署或執行外部掃描。

## Acceptance Coverage

下列清單是應執行的驗證，不是已通過報告；每列須連到實際測試／證據，缺少、未執行或失敗均不得標記完成。[scope SCP-09][practices]

| 驗證場景 | 對應需求 | 通過條件 |
| --- | --- | --- |
| 合法私訊／群組／無效輸入／來源不符 | FR1、NFR2 | 只有合法受支援情境可查詢，其他不越界或保存 |
| 首次位置、拒絕保存、同意後重傳 | FR2、FR5、NFR4 | 未選擇位置不等待／不傳餐廳服務；不保存仍推薦且無持久位置 |
| 一公里邊界、重複店家、營業未知／休息／停業 | FR3 | 正確篩選、排序、去重；理由及地圖均對應候選 |
| 三家／不足／零結果／來源故障 | FR3、FR4 | 數量與狀態真實，不擴圈、不捏造、不混淆失敗 |
| 本人歷史欄位、分頁及他人存取 | FR5、FR6、NFR3、NFR7 | 欄位白名單、每頁五筆、本人限定、不回傳已刪／到期內容 |
| 單筆／全部刪除、取消、過期、重複及跨人確認 | FR7、NFR3 | 五分鐘與範圍綁定有效，無越權／誤刪，分清受理與完成 |
| 撤回、在途寫入、重新同意及延遲事件交錯 | FR7、FR8、NFR2 | 不新增或復活不該保存的舊查詢，不影響合法的新查詢 |
| 曆年、閏日、臺北／UTC 跨日、期限前／當下／後 | FR5.3、FR9 | 每筆獨立一年、到期立即不可見、不被新查詢或重試延長 |
| 24 小時清除、失敗重試、副本檢查與復原 | FR9、NFR4、NFR5 | 全部可控位置內容依限清除、無位置歷史備份、已刪／到期不重現 |
| 事件有效期／併發去重、代碼到期後再重送 | NFR2、NFR4 | 至多一筆歷史，七天代碼消失後仍不接受超過時效舊事件 |
| 保存／查閱／刪除故障、LINE 不可用 | FR4、NFR1、NFR2、NFR5 | 不假稱完整成功或送達，不盲目重送／推播補發 |
| 持續及同時負載、可回覆受控故障 | NFR1 | 完整量測接收／回覆延遲及失敗，逐場景達標，不丟棄失敗樣本 |
| 記憶體生命週期、診斷敏感資料、分類期限 | NFR4、NFR5 | 十秒／七天／30 天等規則與同意狀態清除可驗證，無替代位置歷史 |
| 本機／CI 重現、覆蓋率及安全檢查 | NFR8、NFR9 | 80% 底線、關鍵案例與適用檢查均有結果，未做不算通過 |
| 授權下真實完整流程 | NFR6、NFR8 | 前提具備後 LINE、資料來源、回覆及本人權利均有可重現證據，不只模擬 |
