# 午餐決定器 LINE Bot：第一版範圍

## Scope Summary

第一版讓公司同事、家人與朋友在 LINE 私訊中主動傳送位置，取得附近餐廳建議，減少午餐選擇障礙。同時提供可選擇的一年精確位置與查詢歷史保存、本人查閱及刪除。交付目標是可測試版本，不是正式上線。[S1][S2][S5]

本文件依已確認的範圍摘要產出；仍須本階段核准。範圍列入不等於功能已實作，文件確認也不授權支出或代表真實串接已完成。

## Users and Product Boundary

- 主要使用者是受邀的同事、家人與朋友，各自與 Bot 一對一互動；不預設公司已授權、指定試用人數或任何公司系統可用。[S1][S3 C-12][S5 Q1]
- 餐廳搜尋輸入為 LINE 位置訊息，可能是任意指定地點；不把傳送位置解讀成使用者真實所在或連續行蹤。[S2][S5 Q1]
- 歷史的本人查閱與刪除同樣在私訊進行；「本人」必須經可靠辨識，不能只相信請求宣稱的使用者身分。[S3 C-06][S5 Q1–Q2]
- 帳號、資料來源、費用與法規查核仍屬外部條件；具體技術、介面細節及服務選擇留待後續設計。[S3 C-07–C-13]

## In Scope

以下均為本輪最小完整交付的 **Must Have**；不能把一年歷史或其保護措施降為有空才做。

| ID | 必做能力 | 範圍界線與可觀察結果 | 依據 |
| --- | --- | --- | --- |
| SCP-01 | 私訊位置搜尋與基本引導 | 接受一對一對話中的 LINE 位置訊息；其他輸入有適當引導，不誤作位置。群組不執行推薦或位置歷史功能，也不向群組公開本人歷史 | S5 Q1、Q4 |
| SCP-02 | 附近餐廳推薦 | 以傳送點的直線半徑 1 公里為範圍；候選充足時回覆 3 家不重複餐廳，各有名稱、基於資料的簡短理由及地圖連結 | S1、S2 F-02 |
| SCP-03 | 誠實的結果與失敗處理 | 優先資料顯示營業中，排除明確休息或停業者；未知狀態標示。無結果或不足 3 家時如實回覆；不暗中擴大範圍、虛構餐廳或保證座位。外部故障不能冒充成功或查無餐廳 | S2 F-03、V-02–V-03；S5 Q4 |
| SCP-04 | 告知與保存同意管理 | 清楚區分當次位置處理、第三方傳輸和一年保存。未同意長期保存仍能使用當次推薦，但不新增本專案的位置／查詢歷史；能撤回保存同意並停止新增 | S3 C-06；S5 Q3 |
| SCP-05 | 一年歷史與本人查閱 | 已同意保存時，保留主動查詢的精確位置與查詢紀錄，供本人查看仍在期限內且未刪除的資料，至少可見查詢時間與當時傳送的位置 | S2 F-04–F-05；S5 Q2 |
| SCP-06 | 本人提前刪除 | 可刪除單筆或全部本人歷史；刪除前清楚顯示範圍並由本人確認。撤回保存同意時提供清除既有歷史的操作；不能把撤回保存與已完成刪除混為一談 | S5 Q2–Q3 |
| SCP-07 | 到期清除與資料生命週期 | 每筆查詢獨立起算一年，到期刪除，後續查詢不延長舊紀錄。清除與備份復原不得讓已刪資料重新對本人或他人可見；具體清除時限及副本處置須在需求階段定義 | S3 C-05；S5 已確認摘要 |
| SCP-08 | 隱私、資料權利與處理可靠性 | 本人資料隔離、必要存取保護、來源驗證、重複事件不重複建立紀錄；一般診斷不複製完整位置／訊息或憑證；只處理授權允許的供應方內容與來源標示 | S3 C-06–C-09；S5 Q2–Q3、Q5 |
| SCP-09 | 可重現的驗證與試用交付 | 有執行與測試說明、必要自動化測試及授權條件下的真實完整流程證據；涵蓋推薦例外、本人隔離、拒絕／撤回保存、提前刪除和到期清除，不以模擬測試取代真實串接 | S2 V-01–V-08；S5 Q5 |

既定測試策略及品質要求不因範圍限縮而降低。清單定義使用者成果與必要保護，不指定程式語言、資料庫或部署架構。

## Minimum Complete Release

第一版完成須同時具備 SCP-01–SCP-09。只完成餐廳推薦、只存資料卻不能查閱／刪除，或只通過模擬測試，都不是這輪完整交付。[S5 Q5]

- 正常路徑：本人私訊傳送位置，候選充足時取得範圍內的 3 家餐廳及所需資訊。[S1][S2]
- 例外路徑：不支援輸入、無結果、不足 3 家、營業資訊未知及外部失敗均有可辨識處理，不產生假結果。[S2 V-02–V-03]
- 保存選擇：不同意長期保存時仍可取得當次推薦，且本專案不建立位置歷史；同意後依一年條件保存，撤回後停止新增。[S5 Q3]
- 歷史權利：本人可查閱有效歷史、確認後刪除單筆或全部；另一位使用者不能讀取或刪除這些資料。[S5 Q2][S3 C-06]
- 保存期限：用可控制時間的測試驗證一年邊界、提前刪除、到期清除及必要復原情境，不等待一年才測試。[S2 V-06]
- 真實試用條件：帳號與授權可用、歷史保存權核對、隱私與存取驗證完成，必要費用已獲授權。未達條件可做內部模擬驗證，但不能宣稱真人試用已就緒。[S3][S4]

反應時間、試用人數、清除完成時限、曆年邊界、備份處置等需在需求階段訂定可測試條件；本節沒有替未知值虛構數字。

## Value Stream Map

以文字流程表達，不引入尚未選定的技術：

> 本人開啟私訊 → 理解當次位置處理及保存選擇 → 主動傳位置 → 搜尋與篩選 → 收到餐廳、理由、地圖連結或明確例外說明 → 自行決定午餐。

- **選擇保存**：主動查詢形成有期限的本人紀錄 → 本人日後查閱 → 確認後提前刪除，或到期清除。
- **不選擇保存／撤回保存**：仍可當次推薦 → 不新增本專案位置歷史；既有歷史的清除有獨立操作與義務規則，不假裝已刪除。
- **支援條件**：合法資料、費用授權、資料隔離與必要同意貫穿流程，不是尾端才附加的選配。

對應價值：縮短找午餐的決策過程、保留本人可回顧的查詢、讓使用者控制位置資料。滿意度沿用同事／親友使用幾次後的定性回饋，不發明量化成效。[S1][S5][S6]

## Sequencing and Dependencies

採用已確認的「風險優先、兼顧核心價值」方向：先釐清資料資源、權利與費用條件，再完成私訊推薦及完整歷史保護，最後整體驗證。工作拆分及優先順序見 `intent-backlog.md`；它是初步成果分組，不是正式技術單元或工期承諾。[S5 Q5]

外部依賴沿用 S4 的 D-01–D-04。內部可先用模擬資料進行分段驗證，但真實試用不得繞過身分隔離、同意、提前刪除及到期清除。也不因排程先後而把這些保護降成後補項目。

## Change and Decision Boundaries

- 提出者決定新增／刪減功能或處理費用、授權衝突；同事及親友提供試用意見，不替提出者批准範圍。[S6]
- 若資料權利、費用、期限或能力不符，先回報並請提出者決定，不擅自延長保存、縮短一年承諾、刪掉歷史、降低測試要求或啟用付費。[S3][S5 Q5]
- 具體實作方式由後續需求與設計定義；本次範圍核准不代表任何正式部署或對外傳送資料已獲授權。

## Assumptions & Open Questions

- 仍需驗證 LINE／餐廳資料／測試環境的合法可用性、候選涵蓋率、計價、條款與適用政策；沿用 S4 未關閉事項。
- 後續需求需定義歷史詳細欄位、是否及如何顯示未成功查詢、分頁、刪除確認、保存同意的撤回與既有資料清除義務。
- 反應時間、查詢量、月預算、交期、到期清除完成時限與備份規則未定；不將未知條件視為已承諾或可以忽略。
- 已確認的功能排除僅適用這版，沒有自動產生下一版排程。
