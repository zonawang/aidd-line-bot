## Way of Working

- 我們沿用 `main` 主幹、短期分支及 squash 合併；Construction 的 base／target 均為 `main`。org 的通常 1–2 天是預設節奏，不另捏造本案工期。提出者確認功能與範圍，開發者提供變更摘要及檢查結果，合併前通過適用檢查；有其他協作者時另記錄責任。[Q1][memory:M1]
- 我們維持風險優先的工作方向，先處理資源、資料權利與必要保護，再逐段驗證成果；INT-01–INT-06 是成果分組，後續設計才定義施工單元。參與試用的同事與親友不因此成為開發或合併核准人。[P1][P2][P6]
- 本節確認協作安排，不授權現在建立分支、提交、自動合併或調整 guard；實際託管、CI 服務及其他協作者名單仍未定。[Q1]

## Walking Skeleton

- 我們先用合成位置、合成身分與受控資料串通「位置輸入 → 餐廳查詢介接 → 推薦回覆」的最小內部流程，再逐段補齊推薦例外及完整歷史保護；資源與授權就緒後驗證真實串接。[Q2]
- 第一個切片只證明元件可連接，不固定為第一個 Unit 必須完成全部歷史功能，也不代表 SCP-01–SCP-09 已交付；完整驗證清單適用整個版本。只有推薦、只保存卻不能查閱／刪除，或只有模擬成功，都不是本輪完整成果。[Q2][P2][P6][DEV]
- 真人保存前，我們完成必要告知／同意、可靠本人辨識與隔離、查閱、單筆／全部刪除及到期清除的保護與驗證；真人試用仍須滿足資源、資料權利、安全、適用政策及必要費用授權條件。未同意保存者仍可當次推薦且不新增歷史；不以切片安排延後這些保護。[Q2][P1][P2]
- 活動 scope 原檔未宣告 `skeleton:`；Q2 只採用開發安排，不補成 `on`／`off`、不改 scope，也不宣稱框架儀式已啟用。相依儀式僅在有效 scope 宣告 `skeleton: on` 時按 org 條件處理，`skeleton: off` 時略過；適用時另須實際驗證、經人類授權的 Construction Verification Command 及檢查點核准。現在的 checkpoints `enabled`、`unit-major`、`serial` 不替代上述依據。[Q2][scope][memory:M1][W1]

## Testing Posture

- **Methodology**: test-after
- **Ordering**: 每個可測層實作後立即撰寫並執行該層測試；相依邊界一旦可連接，即完成其整合測試，再擴充下一段功能，最後執行完整流程驗證。

上述方法與順序由 Q3 採用。我們保留 `Standard` 的單元及關鍵邊界整合測試；每元件約 5–8 個測試僅為軟性規劃指引，數量及比例不能排除必要行為、隱私或生命週期案例。[Q3][Q4][W1][F3]

- **行覆蓋率**：我們新增至少 **80%** 的應用可測原始碼行覆蓋率底線，分母包含未被測試載入的應用原始碼；排除依賴、產生碼、AI-DLC 框架及測試本身，排除清單須可審查。這是 Q4 對本自訂 scope 的新採用要求，不是由 Standard 自動推導，也不代表已達標；不得為通過檢查而降低。[Q4][memory:M1]
- **合併前 CI**：我們執行適用建置、格式、lint、單元與關鍵整合測試並檢查覆蓋率；必要檢查失敗、未執行或未達門檻時不能視為通過或合併。既有 org 明文要求 lint 在合併前 CI 執行且失敗阻擋 PR；**格式檢查門檻是 Q4 新採用**，初稿的來源歸類已修正。平台、工具、命令與報告位置留待選定。[Q4][memory:M1]
- **推薦與入口**：我們驗證私訊／群組及無效輸入界線、一公里範圍、候選不足／重複、未知／休息／停業狀態，以及外部故障不得冒充無結果或成功；名稱、理由與地圖須對應實際候選。[P2 SCP-01–SCP-03、SCP-08–SCP-09][QLT]
- **同意與本人權利**：我們驗證未同意仍可推薦且不新增歷史、同意後本人查閱、撤回後停止新增，以及跨人查閱／單筆刪除／全部刪除均被拒絕；來源驗證不能取代本人授權。刪除確認涵蓋範圍、取消、重複與過期情境，其有效期及具體行為留待需求明訂。[Q4][P2 SCP-04–SCP-08][QLT]
- **生命週期交錯**：我們驗證重送與併發不重複建檔、撤回／刪除與在途查詢或延遲事件交錯、每筆一年獨立起算、到期前／當下／之後、清除失敗及必要復原；新查詢不延長舊紀錄，已刪或到期資料不重新可見。以受控時間測試一年邊界，讀取不可見與實體清除完成分別驗證；曆年／時區／閏日算法、生效切點與時限仍待需求化。[Q4][P2 SCP-07–SCP-09][QLT]
- **證據與完整流程**：我們在日常測試使用合成資料與受控供應方回應，檢查一般診斷及失敗路徑不形成替代位置歷史；授權後另保留真實 LINE → 資料來源 → 回覆及本人歷史管理的可重現證據。覆蓋率、模擬成功或安全掃描都不能取代上述關鍵案例與真實串接；未驗證者如實標示。[Q4][P2 SCP-08–SCP-09]
- **安全檢查**：我們納入秘密、依賴與適用的 SAST 原始碼安全檢查；確認有效的外洩憑證及已確認 Critical／High 風險在處置前阻擋合併。必要掃描失敗或未執行不能算通過；誤報與限期例外由提出者檢視依據另行決定，不能取消既有隱私保護。掃描工具、適用性、判讀規則、修補及例外期限待設計，不把工具不存在或掃描涵蓋為零當通過。[Q7][SEC]

## Deployment

- 我們先交付本機可重現的執行與測試方式；真實 LINE 串接所需的非正式環境另行確認資源及授權。若之後設置已授權 staging，沿用 org 的合併後部署規則；本輪仍只交付可測試版本，**不正式上線**。[Q5][memory:M1][P2 OUT-05]
- 本輪 CI 階段在範圍內，Operation 略過；這不豁免已確認的真實流程與資料保護驗證，也不證明環境已可用。本次訪談不授權建立資源、啟用付費或傳送真人資料。[Q5][W1][P1]
- DAST 等執行中服務安全測試，等受控非正式環境與目標授權具備後再安排；不自行掃描 LINE／餐廳供應方，也不擅自把程式、資料或發現內容送到新外部服務。目標範圍、流量／費用限制及停止條件仍待設計。[Q7][SEC]
- 我們維持一般診斷不複製完整位置、訊息或憑證的既有保護；安全與 CI 證據同樣需檢查敏感內容。固定依賴／工具版本、可信來源、CI 最小權限、不受信任變更與秘密隔離，以及證據存取／保存規則屬待設計的控制建議，尚非已部署機制。[P2 SCP-08][Q7][SEC]
- 若採用資料副本或版本復原，其程序不得使已刪除或到期資料重新可見；備份、清除與復原方式由後續需求／設計定義。本稿沒有已演練回復或已通過合規查核的主張。[P2 SCP-07][P1]

## Code Style

- 我們依語言慣例，先讀適用的應用 linter／formatter 設定，只補工具未涵蓋的規則；本機與 CI 使用相同版本及命令。lint 的既有阻擋規則與 Q4 新採用的格式檢查均適用；工具品牌在語言選定後再決定。[Q6][Q4][memory:M1]
- 我們在外部資料進入時驗證來源、型別及合理範圍，歷史操作另核對本人與紀錄歸屬；資料缺漏或營業狀態未知不能因預設值變成營業中。[Q6][P2 SCP-03、SCP-08][DEV]
- 我們明確區分無結果、權限拒絕、外部失敗及保存／查閱／刪除失敗，不把部分成功說成全成功；推薦成功不代表歷史已存入，刪除未完成也不能回覆已刪除。診斷不複製完整位置、訊息或憑證。[Q6][P2][DEV]
- 我們只重試可安全重放的操作，並在後續需求／設計明訂重試與撤回、刪除及重送交錯的行為。錯誤表示法、重試次數／等待上限、去重機制、儲存方案、服務數與資料夾結構均未選定；責任區分不是固定架構。[Q6][DEV]
